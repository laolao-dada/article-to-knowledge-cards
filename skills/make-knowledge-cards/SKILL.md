# Make Knowledge Cards（知识卡片生成）

## Overview

把用户提供的文章（直接粘贴的文本）或本地 Markdown/TXT 文件，提炼为一组知识卡片。每张卡片只讲一个真正重要的知识点，帮助用户快速回顾与自测。本 skill 只做"信息提炼与重组"，不做任何形式的联网抓取、格式转换或界面渲染。

## 何时使用

在以下场景触发本 skill：

- 用户粘贴了一篇文章 / 长文 / 笔记，希望整理成便于记忆的卡片。
- 用户提供了本地 `.md` 或 `.txt` 文件路径，希望转换为知识卡片。
- 用户明确提出"生成知识卡片""做成卡片""提取知识点""帮我总结成卡片"。

不要用于：网页链接抓取、PDF 解析、生成 Anki 牌组、或提供图形界面（详见"不支持的功能"）。

## 输入处理

1. 判断输入来源：
   - 若用户提供本地文件路径（以 `.md` 或 `.txt` 结尾），先读取该文件内容。
   - 若用户直接粘贴文本，以粘贴内容为准。
2. 仅使用用户给出的内容。不要联网、不要读取文件之外的资料、不要引入外部知识。
3. 若文本为空或明显不是文章（如只有一句话、纯乱码），先向用户确认是否提供了完整材料，再决定是否生成。

## 工作流程

1. **通读全文**：把握主题、论证脉络与结论。
2. **抽取知识点**：识别文章中真正重要、可独立成立的知识。优先保留：
   - 核心定义 / 关键概念
   - 关键原理、机制或因果关系
   - 常见误区或易混淆点
   - 实用方法、步骤或原则
   - 对比 / 分类关系
   跳过：客套话、重复表述、与主题无关的举例、单纯的故事叙述（除非其承载了关键结论）。
3. **去重合并**：含义相同或高度重叠的内容只保留一个知识点，避免重复卡片。
4. **控制数量**：
   - 目标 **5~8 张**。
   - 若文章信息量不足，或真正重要的点少于 5 个，**不要强行凑数**——输出少于 5 张，并在开头用一句话说明原因（例如："原文信息密度较低，仅提炼出 3 个核心点"）。
   - 单篇文章最多 8 张；若要点过多，只保留最重要的 8 个，其余忽略，不强行压缩进更多卡片。
   - 要点在 5~8 张之间最佳；不要为了凑满 8 张而把细枝末节单独成卡，宁可少一张。
5. **逐张成卡**：每张卡片严格只讲一个知识点。

## 卡片结构

每张卡片包含四个字段，缺一不可：

- **标题**：一句话点明该知识点的名称（名词或短句，建议 ≤ 15 字）。
- **核心知识**：用一两句话给出该知识点的精炼结论（"是什么 / 关键结论是什么"）。
- **简明解释**：用 1~3 句话补充背景、原理或"为什么重要"，让读者真正理解，而非仅复述标题。
- **例子或自测问题**（二选一）：
  - 例子：一个具体、贴近原文的小例子或应用场景；
  - 自测问题：一个能检验是否理解该知识点的提问（更推荐用于偏概念的内容）。

## 硬性规则

- **只忠实于原文**：所有内容必须来自用户提供的材料。不得添加原文没有的事实、数据、人名、年份、引用或结论。
- **不编造**：当原文信息不足以支撑某个字段时，宁可省略该卡片或该字段，也不要生成臆测内容。
- **一张一知识点**：不要把多个独立结论塞进一张卡片。
- **去重**：删除与已存在卡片重复或几乎重复的内容。
- **不强行凑数量**：信息不足时，如实减少卡片数并说明。

## 输出格式

在回复中直接以 Markdown 输出卡片。建议先给一句总览（如"已从原文提炼 N 张知识卡片"），再逐张列出。输出语言须与输入语言保持一致。

卡片的 Markdown 模板：

```markdown
## 卡片 1：<标题>

- **核心知识**：<精炼结论>
- **简明解释**：<1~3 句解释>
- **例子 / 自测**：<具体例子 或 自测问题>
```

若输入为本地文件，默认将卡片同时写入与源文件同目录的 `<原名>_cards.md`（如 `article.md` → `article_cards.md`），并在回复中展示；若用户明确只要对话结果，则不写文件。写文件前确认不会覆盖已有文件，如已存在则先询问用户。

## 不支持的功能

明确告知用户以下能力不在本 skill 范围内，不要尝试实现或绕过：

- **网页抓取 / 在线抓取文章链接**：本 skill 不访问网络。
- **PDF 解析**：仅接受 `.md` 与 `.txt`。
- **Anki 导出**：不生成 `.apkg` 或其他间隔重复软件格式。
- **图形界面（GUI）**：仅以文本（Markdown）输出。

如果用户提出上述需求，说明限制并给出可行替代（例如：先由用户把网页 / PDF 文本复制进来，再生成卡片；或导出 Markdown 后由用户自行导入 Anki）。

## 示例

输入（节选）：

> 浏览器缓存分为强缓存和协商缓存。强缓存由 Expires 和 Cache-Control 响应头控制，命中后浏览器直接使用本地副本，不再发请求。协商缓存由 Last-Modified / ETag 控制，浏览器仍会发请求，由服务器判断资源是否变化，未变化则返回 304。

输出：

已从原文提炼 2 张知识卡片：

## 卡片 1：强缓存与协商缓存的区别

- **核心知识**：HTTP 缓存分两类——强缓存命中后浏览器不发请求，协商缓存每次都发请求验证。
- **简明解释**：强缓存靠响应头直接决定是否使用本地副本；协商缓存则每次向服务器确认资源是否变化，未变才复用。
- **例子 / 自测**：自测——"什么情况下浏览器完全不会向服务器发请求？"

## 卡片 2：协商缓存的验证机制

- **核心知识**：协商缓存通过 Last-Modified / ETag 让服务器判断资源是否变化，未变化返回 304。
- **简明解释**：浏览器带上上次得到的标识去询问服务器，服务器比对后决定返回新内容还是 304 复用本地副本。
- **例子 / 自测**：例子——首次请求后服务器返回 ETag；再次请求时浏览器带上该 ETag，若文件未改动，服务器返回 304，浏览器复用本地 CSS。
